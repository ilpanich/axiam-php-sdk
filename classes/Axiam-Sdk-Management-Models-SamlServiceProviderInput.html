SamlServiceProviderInput
in package
  • Application
implements JsonSerializable

FinalYes
SamlServiceProviderInput.php : 21

Everything an administrator supplies when registering or replacing a service provider (`create` and `update` both take it; `update` is a full replacement). Every field but `entity_id`, `display_name` and `acs_urls` has a default, so a client written against a later revision of this struct keeps working.

This is a REPLACEMENT body (§27.4 rule 5): what it omits is not preserved. The required members are constructor parameters, so omitting one is a constructor error; an optional member left unset is omitted from the wire and takes its default server-side.

The SP's entityID, unique per tenant. At most [MAX_ENTITY_ID_BYTES].

Whether IdP-initiated SSO is allowed for this SP (D-3). A per-SP opt-in, off by default: an unsolicited assertion has no InResponseTo to bind it to a request the SP made. (optional)

Groups whose members may sign in to this SP. Empty means every active user of the tenant may.* Evaluated by the SSO endpoint (T23.2.3). (optional)

$enabled : bool|null = null

Whether the SP may sign in at all. A disabled SP stays registered but every SSO request for it is refused. (optional)

$encryptAssertions : bool|null = null

Encrypt assertions to the SP's encryption certificate (D-2). Off by default; requires [Self::sp_encryption_cert_pem]. (optional)

NameID policy. Default: persistent, pairwise. (optional)

$signResponses : bool|null = null

Sign the <samlp:Response> envelope as well as the assertion (which is signed always). Default true: it costs nothing and many SPs require it. (optional)
