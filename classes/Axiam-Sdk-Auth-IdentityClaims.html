IdentityClaims.php : 18

Reads the two claims a local role or scope guard decides on, from verified claims (CONTRACT.md §11.2 rule 11, contract 1.68; N15, D-1) — the ONE place both framework bridges ({@see \Axiam\Sdk\Laravel\AxiamMiddleware}, {@see \Axiam\Sdk\Symfony\AxiamAuthSubscriber}) get them from, so Laravel and Symfony cannot drift.

The two claims are never derived from one another. Before contract 1.68 this SDK built the identity's roles from roles ?? scope; a scope is chosen by the client and bounded only by its registration, so any user signed in through a client registered for a scope named like an application role passed that role's guard (N15).

public static roles(array<string, mixed> $claims) : array<int, string>|null

null — the claim is absent, or is not a JSON array of strings — and [] — the claim is present and says the subject holds no role — are deliberately different results: both fail every require_role, but one means "the application did not request the roles scope" and the other "the user holds none" (§11.2 rule 11 (b)).

Never reads scope, never falls back to any other claim.
