Declarative local OAuth2-scope check (CONTRACT.md §11.2 rule 11 (d), contract 1.68; N15) — the canonical `require_scope(scope...)`.

Like RequireRole it is metadata read by the framework-specific enforcement listener (AxiamAccessAttributeListener, AxiamAccessMiddleware), which delegates to AccessEnforcer::enforceScope(), and it is a LOCAL check: it reads the verified token's scope claim (the space-separated list of RFC 6749 §3.3) and never makes a server round-trip. It passes when the token's scopes contain at least one of self::$scopes (whole entries, exact and case-sensitive — administrator does not satisfy admin). A route that needs several scopes stacks the attribute (the attribute is repeatable): the instances are ANDed, so the route passes only when EVERY instance is satisfied, each by at least one of its own scopes — #[RequireScope('documents:read')] #[RequireScope('documents:write')] needs both. Stacking works on a method and on a class; as with the other attributes, instances on the method replace those on the class rather than adding to them.

It reads ONLY scope. A scope says what the client was authorised to ask for, not what the user holds: it is coarser than RequireAccess, which is the authoritative check, and it is no substitute for RequireRole, which reads only the roles claim.

An unauthenticated request is a 401; a token with no scope claim, or one that is not a string, or whose scopes do not contain any required scope, is a 403.
