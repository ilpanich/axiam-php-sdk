CibaRequestSigner.php : 25

The key and algorithm for CIBA's signed authentication request (CONTRACT.md §33.2, CIBA Core §7.1.1). Both are the caller's: there is no default for either, and the SDK signs under exactly the algorithm given — the one the client registered as `backchannel_authentication_request_signing_alg`.

The key material is held only behind Sensitive (§33.5): print_r(), var_dump(), var_export() and json_encode() of a signer show the algorithm and kid, never the key.

Signing uses firebase/php-jwt, this SDK's JOSE library: EdDSA (through ext-sodium) and ES256 (through ext-openssl). PS256 is refused at construction — the library signs it only through phpseclib 3, which this SDK does not depend on (see CibaSigningAlg).
