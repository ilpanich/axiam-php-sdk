NetworkApi extends ManagementSupport
in package
  • Application

FinalYes
NetworkApi.php : 34

A tenant's network segments and the RADIUS reply profile each owns (RADIUS D4): a segment is a node of the reserved /network subtree of the resource tree (kind, VLAN, Filter-Id envelope, placement rank), and its profile is the typed `axiam-radius-reply/1` record a decision renders. Every write is conditional on the `version` the caller read and passes the server's write gate. The tenant's Session-Timeout cap is one more row of it (get_policy, replace_policy): lowering it is always allowed, raising it is allowed and audited. The decision route FreeRADIUS calls is not in this registry.

The network namespace handle (CONTRACT.md §27.2), reached as $client->management()->network(). Every method here goes through the one shared ManagementTransport, so §3 CSRF, the §4 cookie jar, the §5 tenant header, §6 TLS, §16 retry and §19 telemetry apply without this class doing anything to opt in (§27.8).

`PUT /api/v1/network/policy`

public replacePolicy(ReplaceNetworkPolicyRequest $body) : NetworkPolicyResponse

A replacement (§27.4 rule 5), conditional on the policy's version -- 0 for a tenant that has never written one, which is the first write. Lowering the cap is always allowed and raising it is allowed and audited; lowering it never rewrites a profile, it only clamps what a profile reads as (§36.3 rules 6 and 7). It needs network:segments_write at the /network root. Never retried (§36.7). The composed form is the manifest (ManifestBuilder::networkPolicy()).

replaceProfile()

NetworkApi.php : 237

`PUT /api/v1/network/profiles/{segment_id}`

public replaceProfile(string $segmentId, ReplaceNetworkReplyProfileRequest $body) : NetworkReplyProfile

A replacement (§27.4 rule 5), conditional on two versions you read: the profile's own version and the owning segment's segment_version; a stale one is 409 and writes nothing (§36.3 rule 2). Read both (getProfile(), getSegment()) and send every member back. A read is the effective profile: a stored session_timeout_secs above the tenant's lowered cap reads as the cap with session_timeout_clamped: true, so a read-modify-write cannot restore the stored value -- what you send is what is stored, the clamped value from then on, and a value above the current cap is 403 (§36.3 rule 6). Raise the cap first (replacePolicy()), leaving the profile alone, to restore it. Never retried, and never repeated for you (§36.9). The composed form is the manifest (ManifestBuilder::networkProfile()).

NetworkApi.php : 117

`PUT /api/v1/network/segments/{id}`

public replaceSegment(string $id, ReplaceNetworkSegmentRequest $body) : NetworkSegmentResponse

A replacement (§27.4 rule 5), conditional on the version you read: a stale one is 409 and writes nothing (§36.3 rule 2). Read the segment with getSegment(), change what you mean to, and send every member back -- enabled, filter_ids, vlan_id, rank and the version; what you leave out is not preserved. kind, site_key and name are not in the body and never change (rule 4). A change of vlan_id, rank or enabled on a segment that has a profile also needs network:grant (rule 1), and a filter_ids that would strand the profile's filter_id is 409 strands_profile. Never retried, and never repeated for you: a 409 means another administrator wrote, so read again and decide (§36.9). The composed form is the manifest (ManifestBuilder::networkSegment()), which builds this body from the read.
