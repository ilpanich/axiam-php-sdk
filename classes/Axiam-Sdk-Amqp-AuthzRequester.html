The AMQP authorization requester (CONTRACT.md §8 "Signed authorization responses", contract 1.68; N2, D-9). It publishes a signed `AuthzRequest` on `axiam.authz.request` with a private, exclusive, broker-named `reply_to` queue, and accepts an answer only when it verifies as the server's signed response to THAT request.

The one rule that decides the design: verify the received bytes and deliver the same bytes (C2). The signature is checked over the delivery body with its trailing hmac_signature member cut out — never over a re-serialization — and the decision handed to the caller is decoded from those very canonical bytes. A body that re-serializes to something else than it arrived as would otherwise verify one thing and deliver another.

A response is accepted only when ALL of these hold (§8 consumer obligations 1–3):

  1. it parses strictly: a JSON object with no duplicate or case-variant keys, allowed a JSON boolean, tenant_id, nonce and hmac_signature present, the signature the TRAILING member;
  2. HMAC-SHA256(subkey, canonical) equals the signature, compared in constant time, under the subkey of THIS requester's own tenant for the key_version it sent — the response carries no key_version and nothing in it selects a key;
  3. tenant_id equals this requester's tenant, and correlation_id and nonce both match one request still outstanding, which is then retired.

Anything else is nacked without requeue, logged as ONE security event (see self::handleDelivery(); never a signature value), is never an allow, and does NOT complete the request: self::check() keeps waiting for the genuine answer until it times out.

The requester requires an AXIAM server of 1.68 or later (contract 1.68). Such a server signs every authorization response with the tenant's AMQP subkey and answers on the requester's private reply_to queue. A server older than 1.68 ignores reply_to and answers, unsigned, only on the shared axiam.authz.response queue, which this requester never reads: against it every check times out. There is no option to accept unsigned responses (CONTRACT 1.69 §8): no AXIAM server sends one to a reply queue, so an unsigned response can only have been published by someone else, and it is discarded and logged. During a rolling upgrade from a pre-1.68 server, use REST or gRPC authorization until every replica runs 1.68 or later.

PHP is single-threaded, so self::check() blocks while it pumps the transport; several requests can still be outstanding (the pending map is keyed by correlation_id) when a long-running runtime drives it from more than one fiber.

Asks the server whether `$subjectId` may perform `$action` on `$resourceId` (optionally narrowed by `$scope`) and waits for the VERIFIED answer.

public check(string $subjectId, string $action, string $resourceId[, string|null $scope = null ][, float|null $timeoutSeconds = null ]) : AuthzDecision

A response that fails verification or binding is discarded and this keeps waiting for the genuine one until the timeout: a failed verification is never an allow and never completes the request.

Parameters
$subjectId : string

UUID of the subject.

$action : string

The action, e.g. documents:read. Valid UTF-8 without U+2028/U+2029.

$resourceId : string

UUID of the resource.

$scope : string|null = null

Optional single scope narrowing the check.

$timeoutSeconds : float|null = null

Overrides the constructor's timeout for this call; a value that is not finite and positive is refused, never replaced by the default.
