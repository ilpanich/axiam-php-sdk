IdTokenValidator.php : 26

ID-token claim validation — CONTRACT.md §12.4, OIDC Core §3.1.3.7.

PURE logic only: no network, no JWT decoding, no crypto beyond a constant-time compare. The signature half of §12.4 (rules 1–2: alg allowlist, kid lookup, Ed25519 verification, single JWKS re-fetch) lives in JwksVerifier::verifyIdTokenSignature() — the SAME verifier the §10 middleware already uses (§12 forbids forking it). This class holds rules 3–6 (issuer, audience, time, nonce) plus the reason-code vocabulary, so both halves can be unit-tested independently, mirroring the TypeScript reference's oidcIdToken.ts/node/jwks.ts split.

Every failure raises AuthError carrying one of the seven stable reason codes below (CONTRACT.md §12.3 rule 3). Rule 7 (all-or-nothing discard) is enforced by the caller — AxiamClient::oidcExchange() never returns a token set whose ID token failed here, so access_token/refresh_token from the same response are dropped with it.
